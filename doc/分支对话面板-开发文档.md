# 分支对话面板 · 开发文档（macOS 原生）

> 版本：v1.0（定稿）
> 日期：2026-07-25
> 方案：**ACP 客户端 × macOS 原生应用**，消耗 Kimi Code 会员额度

---

## 1. 产品定位

一款 macOS 原生桌面应用：接入 Kimi Code CLI 的完整 agent 能力，核心特色是**「选中回答中的任意文字，就地开启支线对话」**——类似 Codex 的分支追问体验（Zed 目前不具备此能力），并配卡片式树状对话管理。

**使用场景**：与 coding agent 协作时，对回答中的某个名词、某段论述、某次工具调用不理解，无需打断或污染主线程，选中该部分即可在右侧开启一条带上下文的支线追问。

**非目标**：

- 第一阶段不做任何写能力（不改文件、不执行终端命令）
- 不做多人协作、账号体系、云同步（纯本地应用）
- 不做 Windows / Linux 版本

---

## 2. 核心功能需求

### 2.1 主对话（P0）

- 与 Kimi Code CLI 的多轮对话，流式渲染
- Markdown 渲染、代码块语法高亮
- **工具调用展示**：模型调用工具（读文件、搜索等）时在对话流中内联展示工具名、参数摘要、执行状态、结果摘要（可折叠）
- 支持多主线程管理
- 模型/模式切换：跟随 CLI 通过 ACP 暴露的能力（如 Plan 模式），以 ACP 实际支持为准

### 2.2 分支对话（P0，核心功能）

**触发**：鼠标选中 AI 回答（或工具调用结果）中的任意文字 → 浮现「追问」入口 → 右侧支线栏打开新支线。

**实现机制**：

- 开支线 = 新建 ACP session，将「背景上下文 + 选中段落 + 用户追问」拼成首条 user message 发送
- 背景上下文由客户端组装：主线程相关问答原文；历史过长时客户端先压缩为摘要再注入（客户端侧可控的唯一省额度手段）
- 支线内正常多轮追问，历史独立累积
- **支线嵌套**：支线回答中再选中可再开支线，自动携带祖先链上下文
- **结论回流**：支线上提供「合并回主线」，将支线结论压缩为一条补充笔记追加到主线程对话流中（作为客户端注入的一条上下文消息，明确标注来源支线）

**支线侧边栏**：

- 右侧固定栏，多条支线以标签页切换
- 每条支线显示其锚点引文（选自哪段文字），点击引文主对话区滚动到对应位置并高亮

### 2.3 只读权限策略（P0）

CLI 自带完整工具集（读写文件、终端命令），只读通过 ACP 权限请求回调（permission request）在策略层实现：

| 操作类型 | 策略 |
|---|---|
| 读文件 / 列目录 / 搜索 | 自动批准 |
| 写文件 / 编辑文件 | 自动拒绝 |
| 终端命令执行 | 自动拒绝 |

- 策略规则在设置中可见，第一阶段不提供修改入口（硬编码保守策略）
- 所有被拒绝的操作在对话流中以「已按只读策略拦截」标注，保持透明
- 后续版本可开放「终端命令白名单」「逐次询问」等细粒度策略

### 2.4 树状对话管理（P1）

**第一档（P1）：缩进树侧栏**

- 左侧栏：主线程为根节点，支线缩进挂于父节点下，文件管理器式树
- 每个节点为卡片：首条问题摘要、轮数、时间、「已回流」标记
- 点击卡片跳转对应支线；主对话区同步滚动到该支线锚点段落并高亮（**树 → 原文回跳是核心体验**）

**第二档（P2，可选）：画布式节点图**

- 2D 可缩放画布，卡片 + 连线展示分支关系（SwiftUI Canvas 自研布局或引入图布局库）
- 待第一档实际使用后再评估投入

## 3. 成本模型

- 计费方式：**消耗 Kimi Code 会员额度（credits）**，由 CLI 内部计量，客户端无 API token 账单
- 上下文管理、缓存为 CLI 黑盒，客户端可控的省额度手段只有两个：
  1. **播种前压缩**：开支线注入背景上下文时先做摘要（摘要本身也走 CLI，但远小于全量历史）
  2. **支线长度管控**：支线超过默认 10 轮提示「合并回主线并关闭」，防止支线膨胀
- 设置页显示当前 Kimi Code 额度状态（如 CLI/ACP 提供查询能力；若无则引导至官方控制台查看）

## 4. 技术架构

### 4.1 总体结构

```
┌────────────────────────────────────────────────┐
│  macOS App（Swift + SwiftUI）                   │
│  ├─ 主对话区（流式渲染、选区监听、工具调用展示）  │
│  ├─ 右侧支线栏（标签页、锚点引文）               │
│  ├─ 左侧对话树（卡片、跳转、高亮联动）           │
│  └─ 设置（项目根目录、额度、权限策略展示）        │
├────────────────────────────────────────────────┤
│  ACP 客户端层（Swift）                          │
│  ├─ ACP 协议栈：JSON-RPC over stdio             │
│  │   （优先官方 ACP Swift SDK；                 │
│  │    若不可用则封装 Rust ACP SDK 经 FFI 调用）  │
│  ├─ 子进程管理：启动/监控/重启 kimi acp          │
│  ├─ 会话映射：ACP session ↔ 本地分支树           │
│  ├─ 权限策略器：读放行 / 写与终端拒绝            │
│  └─ 分支上下文组装器：锚点引文 + 背景摘要构造     │
├────────────────────────────────────────────────┤
│  本地持久层                                     │
│  └─ SQLite（GRDB）：线程、消息、分支树、回流笔记 │
├────────────────────────────────────────────────┤
│  kimi acp 子进程（Kimi Code CLI）               │
│  └─ agent 循环 / 工具 / 模型 / 额度计量          │
└────────────────────────────────────────────────┘
```

### 4.2 技术选型

| 模块 | 选型 | 说明 |
|---|---|---|
| UI | SwiftUI + AppKit 互操作 | 文本选区监听、精确滚动锚点等需 AppKit（NSTextView 层）辅助 |
| ACP 协议 | 官方 ACP Swift SDK（首选）；备选：Rust ACP SDK + Swift FFI | 需在项目启动时验证 Swift SDK 可用性与版本匹配 |
| 子进程 | Foundation Process + Pipe | 管理 `kimi acp` 生命周期，崩溃自动重启并恢复 session 列表 |
| 存储 | SQLite via GRDB | 结构化本地数据 |
| Markdown/代码高亮 | Splash / Highlightr 等 | SwiftUI 渲染管线 |
| 最低系统 | macOS 14（Sonoma）+ | SwiftUI 特性基线 |

### 4.3 前置依赖

- 用户机器已安装 **Kimi Code CLI** 并完成 `/login`（ACP 子进程复用其登录态，本应用不处理授权流程）
- 启动时检测：CLI 是否存在、版本是否支持 `acp` 子命令、登录态是否有效；缺失则给出引导

### 4.4 数据模型（核心表）

```
threads        主线程：id, title, project_root, acp_session_id, created_at
messages       消息：id, thread_id, branch_id(null), role, kind(text/tool_call/tool_result/notice),
               content, created_at
branches       支线：id, thread_id, parent_branch_id(null),
               acp_session_id, anchor_message_id, anchor_quote,
               seed_context(注入的首条背景), status(open/merged/closed), created_at
branch_notes   回流笔记：id, branch_id, thread_id, summary, merged_at
```

关键设计：`anchor_message_id + anchor_quote` 记录支线「从哪段文字长出」，支撑树→原文回跳；`acp_session_id` 关联 CLI 侧会话，应用重启后可通过 ACP 恢复/续接（以 ACP 实际能力为准）。

## 5. 里程碑计划

| 阶段 | 内容 | 预估工作量 |
|---|---|---|
| B-M1 | Tauri→Swift 项目脚手架；`kimi acp` 子进程管理；ACP 握手、session 建立、纯文本流式渲染 | 3~4 天 |
| B-M2 | 工具调用展示（折叠卡片）+ 权限策略器（只读）+ Markdown/代码高亮 | 3 天 |
| B-M3 | 选中开支线（新 session 播种）+ 支线嵌套 + 结论回流 + 右侧支线栏 | 3 天 |
| B-M4 | 左侧对话树 + 锚点回跳高亮 + 多线程管理 | 2 天 |
| B-M5（可选） | 画布式节点图、Plan 模式 UI、额度展示、写权限细粒度策略 | 视情况 |

B-M1~B-M4 合计约 **2 周**，产出可日常自用的完整版本。

**B-M1 的关键技术验证点**（开工第一天先验证，失败则调整选型）：
1. ACP Swift SDK 是否存在且覆盖当前协议版本
2. `kimi acp` 的握手、session 创建、流式推送、permission 回调的完整链路
3. 支线新 session 注入长背景消息的行为是否符合预期

## 6. 风险与注意事项

1. **ACP Swift SDK 可用性**：官方 SDK 覆盖度以 Rust/TypeScript 为主，Swift 侧若缺失需走 Rust FFI 封装，B-M1 增加 1~2 天
2. **协议演进**：ACP 与 CLI 均在快速迭代，锁定测试通过的 CLI 版本，升级前回归验证
3. **策略层只读**：只读靠权限回调拦截，需在 B-M2 对各类工具调用做穷举测试（含 CLI 未来新增工具类型的兜底拒绝策略：默认拒绝一切非读操作）
4. **额度黑盒**：CLI 内部上下文管理不可控，避免在支线中注入超长背景；超长先摘要
5. **Key 合规**：本应用通过 CLI 本体工作，属官方授权路径，无额外合规风险
6. **分发**：自用阶段直接本地构建；如需分享需处理 Apple 签名/公证，不在第一阶段范围
