## 2026-07-31（B-M1 期间）

- **swift-testing 派生子进程假死**：高度并发 spawn 时子进程卡在 dyld 启动通知阶段（`dyld4::RemoteNotificationResponder::blockOnSynchronousEvent`，sample 实证，与业务代码无关）。凡派生真实子进程的测试套件必须标 `@Suite(.serialized)`。
- **Process dealloc 陷阱**：Process 运行中 dealloc 抛 NSException；等待子进程退出必须全程挂起，返回前确保已退出。
- **acp-swift-sdk JSON 转义**：其 JSONEncoder 把 `/` 转义为 `\/`（`session\/new`），fake agent 按字面 `session/new` 匹配会永不应答、测试挂死——含斜杠 method 须双写法兼容。
- **SDK request id 混用**：initialize=1 为数字，`session/new` 起为 UUID 字符串；fake agent 回显须两种都容忍。
- **swiftpm-testing-helper FD 泄漏**：helper 与测试同进程，孙进程（bash fake agent）继承管道 FD 会让 helper 永远等不到 EOF——supervisor deinit 加 SIGKILL 兜底解决。
- **swift-testing 下自制 withTimeout**：不能用任务组实现（任务组隐式等待不响应取消的子任务），须非结构化竞速。
- **GRDB 7 重载解析**：同名同步/异步 `read`/`write` 重载在 async 上下文优先选异步版，测试直调 db 须 `await`。
- **SQLite 外键顺序**：外键开启时 CREATE TABLE 不得引用未创建的表。branches.anchor_message_id 与 messages.branch_id 循环引用 → anchor FK 不建，由应用层保证。
- **GRDB 离线播种（网络受限期）**：github.com 大传输反复断流（ls-remote 小包正常，浅克隆镜像 15 次重试均失败），最终用户手动下载官方 v7.11.1 zip（commit b83108d1），经 jsDelivr 官方清单 SHA-256 逐文件校验 229/229 一致后建本地镜像播种 SPM 缓存 + insteadOf 离线 resolve（配置已还原）。
- **✅ GRDB 合成哈希收尾（2026-08-01 已解决）**：github.com 直连大传输始终不稳，最终经 gitclone.com 镜像 `git fetch --depth 1` 拿到 v7.11.1 标签，哈希 `b83108d1...` 与 api.github.com 官方记录一致（内容寻址保证完整性），并与本地 zip 逐文件 diff 确认相同；随后用该镜像替换 SPM 缓存中的合成镜像、Package.resolved 改钉真实 revision，build 288s 通过、46/46 测试全绿。经验：本机网络下 api.github.com 与 gitclone.com 可达性远好于 github.com git 端点；哈希可验证时镜像是安全的。

## 2026-08-01（M1-012 期间）

- **actor 隔离的订阅缝**：`SessionStore.events(for:)` 是 actor 方法（同步返回 AsyncStream），非隔离上下文调用须 `await`——驱动缝协议直接声明 `async` 最省事。
- **SwiftUI TextEditor 快捷键**：`onKeyPress(_:modifiers:)` 的 modifiers 形参位置实际是 `phases`（macOS 14 SDK 下 `.command` 无法推断）——Cmd+Return 直接用 Button 的 `.keyboardShortcut` 承载，窗口级生效，TextEditor 无需单独处理。
- **GUI 冒烟从 CLI 验证**：`swift run` 产物可直接后台拉起，swift-log 默认输出到 stdout 可判握手结果；验证完 `kill <app pid>` 即可——应用进程死亡使管道关闭，kimi 子进程 stdin EOF 按 G0 语义 exit 0 自动清理，不留孤儿。
- **裸可执行文件窗口无键盘焦点**：SPM 产物无 .app bundle/Info.plist，macOS 默认 accessory 激活策略，窗口能显示但不能成为 key window——打字全落在终端。修法：AppDelegate `applicationDidFinishLaunching` 里 `NSApp.setActivationPolicy(.regular)` + `NSApp.activate(ignoringOtherApps: true)`。

## 2026-08-01（M1-013 期间）

- **取消 vs 自然终止要区分**：消费循环 `for await` 结束后不能无条件当中断处理——renewSessions 主动 cancel 旧任务时，迟到的 streamEnded 会把新一轮流式消息误标 interrupted（全量测试并行下才暴露的竞态）。修法：循环结束先查 `Task.isCancelled`，主动取消跳过中断标记。
- **重连要换整条 client**：SDK 的 notification handler 绑定旧进程管道，复用旧 ACPClient 重连不可靠——新建 client + 重挂 SessionStore + updateDriver 替换会话层驱动。旧进程垂死响应触发 SDK「unknown request」警告，无害。
- **杀进程恢复冒烟可从 CLI 全链路验证**：拉起 app → awk 找 kimi 子进程 pid → `kill -9` → 看日志依次出现 markAllStale / 二次握手 / session 重建，再杀 app 确认无孤儿（注意别误杀用户自己终端的 kimi 进程）。

## 2026-08-01（M2-007/008 期间）

- **SPM 大依赖拉取（本机网络）**：github.com 直连 fetch GRDB 量级仓库约 8KB/s 且中途僵死；注入系统代理环境变量（`HTTPS_PROXY/ALL_PROXY`，本机 127.0.0.1:2334）后速度正常，但代理会掐断长 HTTP/2 git 流（curl 92 CANCEL）——解法是代理 + 环境变量注入 git 配置 `GIT_CONFIG_COUNT/KEY/VALUE` 强制 `http.version=HTTP/1.1`，不改全局 gitconfig。git fetch 断点续传，重试会推进。
- **swift-markdown 0.8.0 `format()` 语义**：对块级节点会带入块间分隔空行（前导 `\n\n`）；BlockQuote 的 format 每行保留 `> ` 前缀；ListItem 内块带列表缩进——切块后须两端 trim，引用逐行剥 `>`，不能假设 format 返回「干净内容」。
- **Highlightr 线程安全**：基于 JavaScriptCore，非线程安全——封装层用串行队列收敛所有调用，配 NSCache 按 `语言+原文` 缓存，SwiftUI 滚动重建视图不重复高亮。`Highlightr()` 初始化加载 JS 资源可失败，按可失败处理整体退化为无高亮。

## 2026-08-02（M3-001 期间）

- **`NSAttributedString(markdown:)` 不解析行内字形**：当前 SDK 下 `NSAttributedString(markdown:)` 与 `NSAttributedString(AttributedString(markdown:))` 都只记录 `.inlinePresentationIntent`，不落到字体 trait——行内粗斜体/行内码须自行枚举意图加 trait（MarkdownAttributedRenderer 已实现并注释）。
- **锚点坐标单位换算**：SelectionSnapshot 的 start/length 是渲染纯文本的 UTF-16 偏移（NSTextView 原生），AnchorResolver 用 Swift Character 偏移——创建支线锚点时必须 UTF-16→Character 换算，回跳时反向换算（ADR-003 已注明）。
- **并行代理同仓协作**：多 coder 代理同分支并行时，各自用独立 `--scratch-path` 构建，提交只 `git add` 自己的文件；测试遇他方在途编译错误可临时移出其测试文件跑完恢复。

## 2026-08-02（M3-004/005 期间）

- **acp-swift-sdk 不透传 JSON-RPC error**：agent 返回 error 响应或进程死亡时，pending prompt 既不抛错也不完成，永久挂起——任何「发 prompt 等 completed」的编排（ACPSummarizer 等）都必须自带超时兜底（非结构化竞速，不用任务组），这不是可选项。

## 2026-08-02（G3 后 GUI 冒烟排坑）

- **裸 NSTextView 进 SwiftUI 必须自报 intrinsicContentSize**：NSViewRepresentable 包装的 NSTextView 默认返回 noIntrinsicMetric，消息行高度塌陷 → 字体重叠 + ScrollView 内容高度错误无法滚动。修法：子类化经 `layoutManager.usedRect(for:)` 实测排版高度回报（宽度返回 noIntrinsicMetric），`setFrameSize` 宽度变化时 `invalidateIntrinsicContentSize()`；配套 containerSize 高度放开 + maxSize 显式设置（SelectableMessageText.AutoSizingTextView）。
- **updateNSView 不能按属性串比较决定是否重设文本**：NSTextStorage 的字体修正（fixFontAttributeInRange）会在 setAttributedString 后自动改写字体属性（CJK/emoji 触发字体替换），使 `attributedString() != 源` 永真 → 每次 SwiftUI 事务都重设文本 → 无限布局循环（主线程卡死、内存膨胀到 2GB+）。修法：只按纯文本 `string` 比较（渲染器对同内容确定性输出）。诊断手法：卡死时 `sample <pid> 3` 抓主线程栈，loop 会堆在 GraphHost.flushTransactions → updateNSView → fixFontAttributeInRange。
- **布局类 bug 单测不可见**：两个 GUI 冒烟才暴露的问题（高度塌陷/更新循环）单元测试全绿也测不出，NSViewRepresentable 布局行为须靠冒烟覆盖——G3 报告 GUI 冒烟项的价值实证。
